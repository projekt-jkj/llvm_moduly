┃ llvm_moduly ┃
┗━━━━━━━━━━━━━┛
Llvm_moduly is a modular distribution of LLVM  
that aims for consistent behavior across all  
platforms. It achieves this by strictly using  
LLVM tools (clang, lld, …) and LLVM runtime  
libraries (libc++, …). Because LLVM’s C  
standard library implementation is incomplete,  
I use a custom MinGW CRT build on Windows and  
the system glibc library on Linux.

┌──────────────────────┐
│ Repository structure │
└──────────────────────┘
Helper scripts:

– argument_parser.sh
  > Contains the command‑line argument parsing algorithm
  > Shared by all other scripts
  > Also defines basic variables (TARGET, PLATFORM, source paths, …)
– helpers.sh
  > Definitions of helper functions used across multiple scripts
– init_repozitories.sh
  > Assigns programs and libraries to individual modules
– init_repozitories.sh
  > Clones all neccessery repositories
– options/*.sh
  > Definitions of switches for LLVM CMake configuration
– target/*.sh
  > Runs `build_all.sh` with predefined command‑line arguments
  > Serves as both an example and documentation of what is (or will be) supported

– copy-msys-dependencies.sh  
  > Copies dynamic libraries from the MSYS environment used to build llvm_moduly
  > Taken from LLVM MinGW (https://github.com/mstorsjo/llvm-mingw)

Build scripts:

– build_all.sh
 > Runs other scripts according to the selected configuration
– build_llvm.sh
  > Builds and installs LLVM tools, Clang and other programs
  > Runs tests in test configurations
– build_mingw.sh
  > Builds and installs MinGW runtime libraries
– build_llvm_runtime.sh
  > Builds and installs LLVM runtime libraries (compiler‑rt, libc++, …)
  > Runs tests in test configurations

Helper folders:

– source/{project}_{tag} 
  > Cloned source code
– build/{project}_{tag}  
  > Build artifacts for individual projects or components
– install/{module}**  
  > Final module containing all required files (distributed as an independent package)

┌──────────────────┐
│ Script arguments │
└──────────────────┘
All scripts share the same command‑line argument parser (`argument_parser.sh`).  
This means that if a script receives an argument it does not use 
but another script does, it is not considered an error.

Shared arguments:

-llvm={} 
	LLVM version used for downloading sources and building  
	Example: `llvmorg-22.1.8`
-mingw={}
	MinGW version used for downloading sources and building 
	Example: `v14.0.0`
-target={} 
	Target platform for which llvm_moduly is built
	Also the default target platform for the built Clang 
	Format: `${SYSTEM}_${PLATFORM}`
	SYSTEM = OS (`win`, `lin`)
	PLATFORM = CPU architecture (`x64`)
-log={}
	Output file for script logs 
	Default: `/dev/stdout`
-cores={}  
	Number of CPU cores used for building 
	Default: output of `nproc`
-install_prefix={}
	Folder where built programs and libraries are installed.
	Default: `$(pwd)/install`

LLVM‑specific arguments:

-build_type={}
	Determines which parts of LLVM are built and with what optimizations
	Valid values: `release`, `llvm_build`, `llvm_test`, `runtime_build`, `runtime_test`
-architectures={}
	Semicolon‑separated list of architectures supported by the built LLVM
	Example: `AArch64;Mips;WebAssembly;X86;XCore`  
	Special values: `all`, `host`
	For details, see the LLVM documentation.
-clang_tools
	Includes the `clang_tools` module in the build
-lldb
	Includes the `lldb` module in the build
-msys={}
	Copies dynamically linked libraries from the specified MSYS environment (e.g., MINGW64 or UCRT64).
	This allows users to run programs outside MSYS without manually resolving dependencies.

┌────────────┐
│ Motivation │
└────────────┘
A few years ago, I developed a program using standard  
C++ modules. At that time, the ecosystem was  
not mature enough, making the task very  
difficult. The best results came from MSVC,  
but it is tightly coupled with Visual Studio.  
Clang produced slightly worse but acceptable  
results. Development on Windows worked fine —  
but when I tried to build the program on Linux  
using the same compiler version, the build  
failed.

I later learned the issue was caused by  
differences between MSVC STL and libstdc++.  
After some research, I found that these  
differences cannot be easily resolved: MSVC  
does not support Linux, GCC is unreliable on  
Windows, and Clang prefers system libraries  
over its own. Some Clang distributions do not  
include LLVM runtime at all or cannot use it.

LLVM MinGW impressed me the most. It uses a  
complete LLVM runtime and MinGW CRT, making it  
almost perfectly compatible with LLVM runtime  
on glibc. However, LLVM MinGW targets something  
else: a multiplatform toolchain for Windows  
development. I need a consistent multiplatform  
toolchain for native and cross‑platform  
development. It also lacks libclang and other  
LLVM libraries.

Therefore, I decided to create my own  
distribution. My LLVM and MinGW build scripts  
are inspired by LLVM MinGW but simplified,  
cleaned up, and improved.

┌────────────────┐
│ Completed work │
└────────────────┘
The current version includes only the `llvm_clang` module.  
Scripts also support building `clang_tools` and `lldb`,
but these have not yet been built.

The `llvm_clang` module contains:  
–  MinGW runtime (UCRT‑based)  
–  LLVM tools (llvm-ar, llvm-nm, …)  
– Clang  
– LLD  
– Clang resource headers (for all platforms)  
– Bash autocomplete for Clang
